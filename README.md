# Кварта

Next.js-сайт кофейной мастерской с каталогом, адаптивным React-интерфейсом и формой заявок. API принимает `POST /api/lead`, проверяет данные, защищает от повторной отправки одного номера в течение 10 минут и сохраняет заявку. `GET /api/health` проверяет доступность API и базы.

## Реализация и вклад

Я определил архитектуру приложения, API-маршруты, способ хранения заявок и состав React-интерфейса, проверял результат и выбирал поведение сервиса. ИИ помогал с реализацией: написал значительную часть кода маршрутов и Sequelize-модели, подключил React-страницу и форму, сделал валидацию, CSS и отдельные функции для работы с заявками и отправки уведомлений. Поэтому готовые части кода и их тестирование я проверял отдельно, а не считал ответы ИИ гарантированно правильными.

## Хранение заявок

Выбрана SQLite через Sequelize. Для учебного проекта и одного экземпляра приложения она не требует отдельного сервера БД, хранит заявки в одном файле `data/leads.sqlite` и поддерживает транзакции. Транзакция нужна, чтобы проверка на дубликат и создание заявки выполнялись согласованно. Хранить заявки в JSON-файле было бы проще, но параллельные запросы и проверка уникальности потребовали бы отдельной синхронизации. SQLite здесь рассчитана на локальный запуск или сервер с постоянным диском; для serverless или нескольких экземпляров приложения нужна внешняя постоянная БД.

## Telegram и ограничения

После записи новой заявки API отправляет уведомление в Telegram, если в локальном `.env.local` заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Telegram выбран как простой канал оперативно увидеть заявку; источником данных остаётся SQLite. Сбой Telegram не отменяет сохранение заявки и не меняет ответ `201`, но записывается в серверный лог. Очереди и повторной доставки пока нет: для production я бы добавил таблицу исходящих уведомлений (outbox) и фоновую отправку с повторами.

В ходе проверки ИИ запустил Lighthouse на dev-сервере, который во время пересборки отдавал 500 и 404 для клиентских файлов. Это приняли за проблему сайта; причину установили по 404 для `/_next`-ресурсов и процессу `next dev`. Повторный запуск на production-сборке прошёл без ошибок запросов. Ещё один исправленный промах — тестовые Telegram-данные попали в `.env.example`; файл очищен, реальные настройки следует хранить только в `.env.local` и не коммитить. Перед передачей проекта токен, опубликованный в примере, нужно отозвать через BotFather.

Для локального запуска: `npm install`, затем `npm run dev`. Сборка проверяется командами `npm run typecheck` и `npm run build`.
